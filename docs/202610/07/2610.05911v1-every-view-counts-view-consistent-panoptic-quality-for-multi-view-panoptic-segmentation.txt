## ABSTRACT 

Multi-view panoptic segmentation assigns a semantic class and a scene-level in-stance ID to every pixel of an unordered set of images, and recent feed-forward 3D models predict these labels for the input views in a single forward pass. Their predictions, however, have been evaluated with the scene-level PQ (PQ scene ) bor-rowed from per-scene optimization methods, typically on rendered held-out views. PQ scene tiles all views of a scene into a single image, so that a missed appearance or a change of ID lowers the score of the matched pair only in proportion to its area. We propose View-Consistent Panoptic Quality (VC-PQ), which extends PQ from a single image to a set of input views, counts equally every view in which an in-stance is visible, and penalizes a prediction that is not visible in the same views as its ground truth. A decomposition of VC-PQ attributes the score a method loses to mask accuracy, view consistency, and the matching threshold. A single additional parameter recovers the area weighting of tiling for comparison. Under a fixed evaluation protocol on ScanNet++ and ScanNetv2, recent feed-forward methods are evaluated with VC-PQ and PQ scene , and the decomposition shows where each of them loses its score. Controlled perturbations of the ground truth show that VC-PQ responds to the number of views in which an instance is missed or changes ID, whereas PQ scene responds to their area. The aim of this work is to make view con-sistency part of the evaluation of multi-view panoptic segmentation, with VC-PQ reported alongside PQ scene .

## 1 INTRODUCTION 

Multi-view panoptic segmentation assigns a semantic class and a scene-level instance ID to every pixel of the images captured from several views of a scene, so that one object instance carries the same ID in every view in which it appears (Fig. 1a). Unlike in video segmentation and object tracking, the input views are captured in an arbitrary order, with no continuity from one view to the next, and therefore this consistency of identity across views is the demanding part of the task. The chairs in a lounge, for example, often look alike (Fig. 1a), so when the viewpoint changes, appearance alone may not tell whether the chairs in different views are the same instance. Per-scene optimization methods lift the outputs of a 2D segmentation model into a 3D scene rep-resentation that is optimized for each scene given precomputed camera poses, and the shared rep-resentation enforces label consistency across views (Siddiqui et al., 2023; Bhalgat et al., 2023; Ye et al., 2024). Recent feed-forward 3D reconstruction models (Wang et al., 2024; 2025) predict the 3D geometry of a scene from the images alone, without precomputed camera poses. Building on their geometry-aware features, feed-forward methods for multi-view segmentation predict instance or panoptic labels with consistent IDs for the input views ( ˇ Zust et al., 2025; Zhu et al., 2026b; Qu et al., 2026; Li et al., 2026b). How these predictions are evaluated, however, has not followed the task. Predictions for this task have commonly been evaluated with the scene-level Panoptic Quality (PQ scene ) of Panoptic Lift-ing (Siddiqui et al., 2023), which applies PQ (Kirillov et al., 2019) to held-out views rendered from the per-scene representation, and feed-forward methods have adopted this protocol ( ˇ Zust et al., 2025; Zhu et al., 2026b) although they predict on the input views. PQ scene moreover tiles all views of a scene into a single image before applying PQ, so that a missed appearance, or a change of ID, in one view lowers the score of the matched pair only in proportion to the area of that appearance (Fig. 1b). The same instance appears at a smaller scale in a view captured farther from it and covers fewer pixels in a view where other objects occlude it, so the weight a view carries in its score depends largely on the camera pose within the scene. We therefore propose View-Consistent Panoptic Quality (VC-PQ), which extends PQ from a single image to a set of input views and scores each instance jointly by the accuracy of its masks and by whether it is visible in the same views as its ground truth, with every such view weighted equally. Apart from a visibility threshold that disregards noisy appearances of only a few pixels, VC-PQ reduces to PQ for a single view. A decomposition of the score lost under VC-PQ attributes it to mask accuracy, view consistency, and the matching threshold, and a one-parameter family of pair scores isolates the area weighting of tiling. We evaluate both metrics under a fixed protocol on ScanNet++ and ScanNetv2 that draws input sets of several sizes from every scene. Each method is evaluated with its native post-processing, and with an adapter where it does not output panoptic labels. Controlled perturbations of the ground truth show that VC-PQ responds to the number of views in which an instance is missed or changes ID, whereas PQ scene responds to their area. As the input set grows, PQ scene rises whereas VC-PQ falls on recent feed-forward methods, and the one-parameter family traces the fall to the equal weighting of views. In summary, our contributions are as follows. • A formulation of multi-view panoptic segmentation on the input views, with two require-ments that a metric for this task should meet (Sec. 3). • View-Consistent Panoptic Quality, which weights every view in which an instance is visible equally, penalizes a prediction that is not visible in the same views as its ground truth, and reduces to PQ for a single view, with a one-parameter family that isolates the area weighting of tiling (Sec. 4). • An evaluation protocol on ScanNet++ and ScanNetv2, under which VC-PQ and PQ scene are compared on recent feed-forward methods and their difference is attributed to each property of PQ scene (Sec. 5.1–5.3). • A decomposition of the lost score by mask accuracy, view consistency, and the matching threshold, which separates the errors within single images from those that arise only across views (Sec. 4.3, Sec. 5.4). 2Preprint 

## 2 RELATED WORK 

2.1 MULTI -VIEW PANOPTIC SEGMENTATION 

Methods that assign semantic, instance, or panoptic labels to the views of a scene follow one of two approaches, per-scene optimization or feed-forward prediction. Per-scene methods lift the predic-tions of an external 2D segmenter into a 3D scene representation, a neural field or 3D Gaussians, that is optimized for each scene given precomputed camera poses, and evaluate the labels rendered from it (Siddiqui et al., 2023; Bhalgat et al., 2023; Zhu et al., 2024; Ye et al., 2024; Liu et al., 2025; Dhiman et al., 2026). Recent feed-forward 3D reconstruction models have progressively removed both requirements. DUSt3R and its extensions (Wang et al., 2024; Leroy et al., 2024; Cabon et al., 2025) predict point maps without camera poses, and VGGT (Wang et al., 2025) predicts camera poses, depth maps, and point maps for a whole set of views in one forward pass. Feed-forward segmentation methods are built on these reconstruction models as a geometry backbone, predict the labels for the input views without a per-scene optimization, and differ in how an instance identity is derived from the geometry-aware features of the backbone. One group predicts a per-pixel or per-Gaussian instance embedding and clusters it into instances at inference, so that an ID is a cluster label and holds across views only as far as the clustering keeps an instance in one cluster (Li et al., 2026b; Zhu et al., 2026b; Koch et al., 2026; Jiang et al., 2026). The other shares a set of object queries across all views, so that an ID is a query index and is the same in every view by construction, and which query covers an instance in each view is left to a post-processing selection of masks or to training alone ( ˇ Zust et al., 2025; Xu et al., 2025; Barberteguy et al., 2026; Qu et al., 2026; Li et al., 2026a). Among the feed-forward methods, PanSt3R, EPS3D, Pano3D, and SIU3R produce panoptic labels, and PanSt3R and EPS3D report panoptic quality with the scene-level protocol of per-scene methods, at novel views rendered from 3D Gaussians rather than on the input views ( ˇ Zust et al., 2025; Zhu et al., 2026b). 2.2 EVALUATION METRICS 

Panoptic Quality (PQ) (Kirillov et al., 2019) scores a single image by matching predicted and ground-truth segments one-to-one and counting every segment equally regardless of its area. Panop-tic Lifting (Siddiqui et al., 2023) extends it to a scene as PQ scene by tiling the views of a scene into one image and reports it at held-out test views, and later per-scene and feed-forward methods adopt this metric (Bhalgat et al., 2023; Zhu et al., 2024; Liu et al., 2025; Dhiman et al., 2026; ˇ Zust et al., 2025). In video panoptic segmentation, PQ is extended by matching tubes over consecutive frames, as in VPQ (Kim et al., 2020; Qiao et al., 2021), or by combining an association term with a segmen-tation term without matching, as in STQ (Weber et al., 2021; Mei et al., 2022; Ayg¨ un et al., 2021); both pool the pixels of several frames, over a window for VPQ and over the whole sequence for STQ. For the consistency of an instance across views, tracking evaluation offers a form that PQ does not have. It scores a given target by its overlap in each frame, averaged with equal weight over the frames, and by the fraction of frames in which it is tracked ( ˇ Cehovin et al., 2016; Huang et al., 2021). Recent multi-view methods score a given instance in the same form, by its mean per-view IoU and by whether it is tracked in every view (Li et al., 2026b; Zhu et al., 2026a). Others match instances by IoU without classes and report a mean IoU and an F-score (Zhu et al., 2026b; 2025), and with the instance given or the class dropped, none of these scores panoptic labels with a class-wise matching and a count of unmatched instances. VC-PQ (Sec. 4) keeps the matching and unmatched terms of PQ and counts every view in which a matched pair is visible equally, in the form of these measures. 

## 3 PROBLEM SETTING 

3.1 TASK FORMULATION 

Given N RGB images I1, . . . , I N of a static scene, captured from N views in an arbitrary order, the task is to predict for each view a panoptic label map Yi.3Preprint The panoptic label map Yi assigns every pixel u of Ii a panoptic label Yi(u) = ( c, z ) (Kirillov et al., 2019), consisting of a semantic class c and an instance ID z. Instance IDs are defined at the scene level. That is, pixels sharing an ID, whether in the same or in different views, belong to one object instance and carry the same class. We refer to an instance by its ID and write c(·) for its class and 

Mi(·) for its mask in image Ii, so that Mi(z) = { u | Yi(u) = ( c(z), z ) }, which is empty when the instance does not appear in Ii. Each stuff class is treated as a single instance. Ground-truth instances are denoted by g and predicted instances by p, with their masks Mi(g) and 

Mi(p) defined from the respective label maps in the same way. An ideal prediction places predicted and ground-truth instances in one-to-one correspondence such that every corresponding pair (p, g )

satisfies c(p) = c(g) and Mi(p) = Mi(g) for every image Ii.3.2 EVALUATION REQUIREMENTS AND EXISTING METRICS 

Evaluating multi-view panoptic segmentation means measuring how closely predicted instances ap-proach the ideal correspondence of Sec. 3.1 across the input views. A metric that captures this ideal should therefore (i) reflect the mask accuracy of an instance in every view in which it appears, inde-pendent of its apparent size in that view, and (ii) penalize a predicted instance by how far the set of views in which it appears departs from that in which its ground-truth counterpart appears. For a single image Ii, Panoptic Quality (PQ) (Kirillov et al., 2019) scores a predicted instance p

against a ground-truth instance g of the same class by the intersection over union (IoU) of their masks, IoU i(p, g ) = |Mi(p) ∩ Mi(g)|/|Mi(p) ∪ Mi(g)|, and matches predicted and ground-truth instances one-to-one among the pairs with IoU i(p, g ) > 0.5, which makes the matching unique. Matched pairs, unmatched predicted instances, and unmatched ground-truth instances are counted over the dataset as true positives (TP), false positives (FP), and false negatives (FN). PQ then divides the summed IoU of the matched pairs, each taken in the image i that contains the pair, by the number of matches with a penalty of one half for every unmatched instance,

The official implementation further discards, before matching, every class that covers less than 0.5% of the labeled pixels of the scene in either the prediction or the ground truth. The feed-forward methods that report PQ scene evaluate under this novel-view protocol, by feeding rendered held-out views to the network or by rendering their labels from a 3D field ( ˇ Zust et al., 2025; Zhu et al., 2026b). We evaluate their predictions on the input views, as the task requires. An input set, like a video clip, contains several views of one scene in which an instance keeps its ID from view to view, which suggests Video Panoptic Quality (VPQ) as a metric for this setting. VPQ (Kim et al., 2020; Qiao et al., 2021) matches predicted and ground-truth tubes within a window of k consecutive frames and averages the score over several window lengths. Within a window, a pair of tubes is scored by the same concatenated IoU of Eq. (2), with the sums running over the frames of the window. In this setting, three properties of PQ scene no longer match the task (Fig. A2, Appendix D). First, Eq. (2) sums pixel areas over views, so that each view weighs in proportion to the area the pair covers in it. Accurate segmentation where an instance appears large then compensates for a complete miss where it appears small, as for the orange ball of Fig. 1b, and requirement (i) is not met. A view in which only one of the two appears has an empty intersection and adds its area to the denominator alone, so a missed or spurious appearance lowers Eq. (2) only in proportion to the area it covers 4Preprint in that view, and requirement (ii) is not met either. Both requirements thus turn on the same area weighting, which PQ scene and VPQ share. Second, PQ scene yields one value per scene, and results for a dataset are reported as the average of these values across scenes ( ˇ Zust et al., 2025; Zhu et al., 2026b). The scene thus plays for PQ scene 

the role that the image plays for PQ, yet PQ does not average over its unit, since the counts of TP, FP, and FN are pooled over all images before PQ is computed for each class (Kirillov et al., 2018). Averaging scene values instead gives every scene the same weight, so that a scene with only a few instances, all of them found, enters the average with a value close to the maximum. For this task, the labels of the N input views are predicted together, and the input set, rather than the scene, therefore takes the place of the single image of PQ. Third, the 0.5% class filter of the official implementation excludes every class that falls below the threshold in the ground truth, where its instances are small or seldom visible, or in the prediction, so that the set of scored classes depends on the prediction under evaluation. Because the threshold is a share of all labeled pixels, a class that appears in only some of the views is more likely to fall below it in a scene with many views. Standard panoptic and instance segmentation (Kirillov et al., 2019; Lin et al., 2014) exclude no class on account of its size. A metric for this task should therefore meet requirements (i) and (ii) and count over the dataset with the input set in place of the image. 

## 4 VIEW -C ONSISTENT PANOPTIC QUALITY 

4.1 DEFINITION 

To this end, we propose View-Consistent Panoptic Quality (VC-PQ), which extends PQ from a single image to a set of views. VC-PQ takes the input set of N views as its unit of evaluation. Within each set, each pair of a predicted instance p and a ground-truth instance g of the same class receives a pair score q(p, g ) ∈ [0 , 1] .An instance x, whether predicted or ground truth, is regarded as visible in view i when its mask Mi(x) has at least η pixels, and its visibility support V (x) is the set of these views, 

V (x) = { i | | Mi(x)| ≥ η }, where η is a visibility threshold specified in pixels at the evaluation resolution and set to 100 following PanopticNeRF-360 (Fu et al., 2025). VC-PQ addresses each of the three properties of Sec. 3.2 in a way that matches the task. In contrast to the area weighting of tiling, every view in the union of Eq. (4) contributes one term regardless of how large the instances appear in it, so that a missed or spurious appearance lowers the score by one term whatever its area. In place of per-scene averaging, matching within the input set and counting over the dataset keep the structure of PQ. The visibility threshold η, the only size-related criterion in VC-PQ, keeps tiny fragments of noisy annotation or prediction from enlarging the union in Eq. (4). It acts on individual appearances rather than on classes, so that an instance is excluded from evaluation only when its mask falls below η pixels in every view of the set. Apart from the visibility threshold, VC-PQ therefore differs from PQ only in how a pair is scored, and with a single view, where q(p, g ) equals IoU i(p, g ), it coincides with PQ. ## 5 EXPERIMENTS 

5.1 EVALUATION PROTOCOL 

We evaluate on the validation splits of ScanNet++ (Yeshwanth et al., 2023) and ScanNetv2 (Dai et al., 2017). ScanNet++ provides 50 validation scenes, each captured twice, with a DSLR camera and with an iPhone, 1 and we use its panoptic benchmark of 100 classes, 84 things and 16 stuff. ScanNetv2 provides 312 validation scenes with 20 classes, 18 things and 2 stuff. For each scene we sample 120 views with a fixed seed and split them at random into input sets of 

N views, so that the views of a set are spread over the scene with no continuity from one view to the next (Sec. 3.1). Every method receives the same input sets and predicts a panoptic label map for each view of a set. We take N = 10 as the default, following the multi-view pose evaluation of feed-forward reconstruction on 10 random frames per sequence (Wang et al., 2024; 2025), and vary 

N ∈ { 5, 10 , 20 , 40 } below and above it in Tables 1 and 3. Panoptic Lifting computes PQ scene over the held-out views of each scene, one quarter of its frames, and averages it over the 26 scenes of its benchmark. To score the same input as VC-PQ, we treat each input set as the views of a scene, as feed-forward reconstruction does, tile it into a single image as in the official implementation (Siddiqui et al., 2023), and sum the counts of the sets of a scene into one value per scene before averaging over scenes. For both metrics, void pixels are handled as in PQ (Kirillov et al., 2019): predicted pixels on ground-truth void are removed from the prediction, and an unmatched predicted instance with more than half of its pixels on void is not counted as FP. Further details of the protocol are given in Appendix A. 5.2 EVALUATING FEED -FORWARD METHODS 

We evaluate four publicly available feed-forward methods: PanSt3R ( ˇ Zust et al., 2025) in its two re-leased versions (v1 and v2), EPS3D (Zhu et al., 2026b), IGGT (Li et al., 2026b), and SegVGGT (Qu et al., 2026). PanSt3R and EPS3D output panoptic labels and are run with their native post-processing. IGGT outputs class-agnostic instances, which we label with the open-vocabulary model LSeg (Li et al., 2022) as EPS3D does. SegVGGT outputs thing instances, which we turn into panop-tic labels with the panoptic inference of Mask2Former (Cheng et al., 2022) and evaluate over its thing classes (Table 3 and Appendix C). The two metrics score the same predictions of each method, so the comparison between them does not depend on how the methods were trained. Table 1 reports PQ scene and VC-PQ of the same predictions at all input set sizes. EPS3D and IGGT score low under both metrics, which we attribute to how they form instances (Appendix C). PanSt3R v2 scores above v1 under both metrics, and for both versions the two metrics move in opposite directions as N grows. PQ scene rises from 46.8 at N = 5 to 57.7 at N = 40 for v2 on ScanNet++ and from 50.1 to 57.4 on ScanNetv2, whereas VC-PQ falls for every method, from 24.5 to 20.0 and from 43.7 to 40.6 for v2. Overall, VC-PQ is lower than PQ scene for every method and every N .Sec. 5.3 traces both differences to the three properties of PQ scene .

5.4 ERROR DECOMPOSITION 

Table 3 applies the decomposition of Eq. (7) to each method over thing classes, for which an ID across views is defined. The first term collects the errors within single images and the other two those that arise only across views (Sec. 4.3), so that the table reads as two shares. For every method and every N the largest term is εIoU , above 90 for EPS3D and IGGT and 44 to 74 for the others, and it changes little with N . Most of the score is thus lost within single images. The two terms across views are what VC-PQ is designed to penalize. εVC collects the instances whose views disagree severely, with the prediction and the ground truth sharing at most half of the views in which either appears. εq collects the instances whose views disagree and whose masks are inaccurate, neither enough to fail on its own, so that the product of the two falls below the matching threshold. Together, the two terms measure how much of the score a method loses to the multi-view setting. As N grows, εVC changes little and in no consistent direction, so the severe disagreements across views remain a roughly constant share of the score. εq instead rises for every method and dataset, from 1.4 to 6.8 for PanSt3R v2 on ScanNet++ and from 2.0 to 7.1 on ScanNetv2, so more instances fall below the matching threshold on the combination of the two factors. Since εIoU also changes little, the fall of VC-PQ with N is accounted for by this term. Appendix E traces the rise to the predictions rather than to the metric, since an instance is matched with the same probability at every 

N given the fraction of the input set in which it is visible, and larger sets hold more instances that are visible in only a few views (Figs. A3 to A4). The decomposition thus shows in which respect each method loses its score, and hence in which direction it should improve. PanSt3R v2 improves on v1 in εIoU , whereas its εVC and εq are larger. On ScanNetv2 SegVGGT is ahead of PanSt3R v2 in all three terms, most in εIoU . EPS3D and IGGT lose nearly all of their score before view consistency enters. 

## 6 CONCLUSION 

We have formulated multi-view panoptic segmentation on the input views and proposed VC-PQ, which counts every view in which an instance is visible equally and penalizes a prediction that is not visible in the same views as its ground truth. On recent feed-forward methods the two metrics move in opposite directions as the input set grows, which varying the area weighting through γ traces to the equal weighting of views. The decomposition separates the score lost within single images from the part that the multi-view setting costs. We hope that VC-PQ will be reported alongside PQ scene ,and that the decomposition serves to locate where a method loses its score and thus to guide its development in the right direction. VC-PQ is defined for a static scene and a fixed set of input views, and the evaluation covers indoor scans of two datasets and four methods. In indoor scans the ground-truth masks are projected from 3D annotations and are therefore noisy, and VC-PQ, which counts every view equally, can be sen-sitive to such noise in the mask of an individual view (Table A8). The visibility threshold η and a slight area weighting through γ, which shifts weight toward the views in which an instance appears large, are the two means the metric provides against such noise. 9Preprint

## A EVALUATION PROTOCOL DETAILS 

ScanNet++ has 50 validation scenes, each captured with a DSLR camera at 920 × 613 and with an iPhone at 960 × 720 , and ScanNetv2 has 312 validation scenes at 1296 × 968 . From every capture we sample 120 views with seed 42, shuffle them, and slice the sequence into input sets of N

consecutive elements, which gives 24, 12, 6, and 3 sets per scene for N = 5 , 10 , 20 , 40 . Within a set the views are ordered by their capture index. At N = 10 a set holds on average 51.2 ground-truth instances above the visibility threshold on the DSLR captures, 44.0 on the iPhone captures, and 13.9 on ScanNetv2. For comparison, Panoptic Lifting reports PQ scene on 26 scenes of HyperSim, ScanNet, and Replica (6, 12, and 8 scenes), with one quarter of the frames of each scene held out as test views (Siddiqui et al., 2023). PanSt3R v1 assigns pixels to queries by simulated annealing, which is run once per input set without a fixed seed, so a second run of the same set can give a different label map. Between two such runs on the same input sets, PQ scene differs by at most 0.6 and VC-PQ by at most 0.1 at N = 10 on either camera. PanSt3R v2 is run with its released two-pass assignment and class-score threshold of 0.1. EPS3D receives the full frames of a set and does not run at N ≥ 20 on a 24 GB GPU, nor does the clustering of IGGT. PanSt3R and EPS3D are trained on ScanNet++, EPS3D also on ScanNet, and IGGT on ScanNet++ among other datasets. The training split of EPS3D on ScanNet++ is not specified, so an overlap with the validation scenes cannot be excluded, and the comparison across methods does not control for training data. IGGT outputs an instance embedding per pixel and clusters it over the views of a set. Each cluster is given the class whose text embedding is closest to the average of the LSeg (Li et al., 2022) pixel features over the cluster mask, with the same prompts as EPS3D. SegVGGT is run from its released checkpoint on ScanNetv2, and its instance masks and class scores are turned into a panoptic label map with the panoptic inference of Mask2Former (Cheng et al., 2022), and pixels that no mask claims are void. Its masks are binarized at 0.4, masks with fewer than 200 pixels are dropped, each query takes its highest-scoring class, its class score is multiplied by the mean mask probability (obj normalization), and no threshold is applied to the class score. Table A7 gives the perturbation of Sec. 5.3 at its operating point, with the three variants of each perturbation and the four scores. We take the ground-truth label maps of the ScanNet++ DSLR runs at N = 10 , restricted to thing classes, apply a perturbation, and score the result against the original, so that the unperturbed maps score 100 under every metric. An appearance is a pair of an instance and a view in which it is visible, and the two perturbations act on appearances. A missed appearance removes the instance from the view, and an identity split gives its pixels in that view a new ID of the same class. Both act on the same number of appearances per instance, about 30% of the views in which it is visible, which amounts to 28% of all appearances at the operating point. They differ only in which views are chosen, namely the views in which the instance appears smallest, those in which it appears largest, or views drawn at random. The operating point lies below the share of appearances that PanSt3R v2 misses on the same runs (55%) and far above the share of appearances it covers with an ID other than the one it gives the instance in most views of the same input set (1.1%). In addition to the two metrics, the table reports VC-PQ 1, which applies the area weighting alone, and per-image PQ, which scores each view independently and is therefore unaffected by a change of ID across views. The VC-PQ column is identical across the three variants, as predicted before the run, and VC-PQ 1 follows PQ scene , which places the difference between the two metrics on the area weighting rather than on the counting or the visibility threshold. Since q(p, g ) is the product of the two factors, the pairs with q(p, g ) = 0.5 lie on the curve 

VC( p, g ) = 0 .5/IoU( p, g ), and the region between this curve and the two lines at 0.5 holds the pairs that pass both tests but not their product. In the classification of unmatched instances (Sec. 4.3), the test on IoU( p, g ) precedes the test on VC( p, g ) because VC( p, g ) compares supports alone and equals one for any two instances that are visible in the same views, so that a candidate whose mask does not overlap with g carries no evidence about g, however consistent its support. For instance, an instance with one candidate at IoU = 0 .2, VC = 1 and another at IoU = 1 , VC = 0 .5 falls in 

FN VC , whereas testing view consistency first would place it in FN IoU . The candidates of an un-matched ground-truth instance are all predicted instances of the same class in the input set, matched or not, and likewise for an unmatched predicted instance with the roles of p and g exchanged.
